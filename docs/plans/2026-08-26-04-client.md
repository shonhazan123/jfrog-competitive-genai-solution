## Design direction — read before Task 1

Two prior artefacts exist and **each contributes exactly one thing**:

| Source | Take | Reject |
|---|---|---|
| **Figma output** | The left sidebar navigation — grouped `DAILY` / `REFERENCE` / `TOOLS` — and the top status strip | Everything else: palette, spacing, and the card treatment |
| **HTML mockup** | Content, density, and card anatomy | Nothing structural; it is the better reference of the two |

### The diagnosis of why the Figma screens felt shallow

The Figma card collapses the **so-what** *and* the **evidence** behind a chevron. What remains on the surface is a chip, a score and a headline — nothing to actually read. That is over-applied progressive disclosure, and it is the single reason those screens look empty.

**The corrected rule, which governs this entire plan:**

> **Always visible:** entity, signal type, score, headline, the full so-what, the verbatim quote, and its source line.
> **Collapsed by default:** only the score breakdown and the production trace.

A reader must be able to answer *"do I care?"* **and** *"why?"* without clicking anything.

### Type scale — deliberately larger than a typical dashboard

```
--fs-display  32px / 1.15 / 700     page titles
--fs-h1       26px / 1.20 / 650     screen headers
--fs-h2       20px / 1.30 / 600     panel titles
--fs-headline 18px / 1.35 / 600     card headline
--fs-body     15px / 1.60 / 400     so-what, prose
--fs-quote    15px / 1.55 / 400     evidence (italic serif)
--fs-meta     13px / 1.45 / 500     source, date, labels
--fs-mono     13px / 1.40 / 500     grades, scores, diffs
```

### Three colour systems on one card, on three different visual channels

This is the hardest visual problem in the product. They coexist because **each owns a different channel**, so they cannot compete:

| System | Channel | Treatment |
|---|---|---|
| **Signal type** (9 values) | **Hue** | Vivid saturated accent — 4px left border on the card + a tinted chip |
| **Materiality** (0–100) | **Weight & intensity** | A mono badge that grows in weight and fill as the score rises. Never a traffic light. |
| **Reliability grade** (A2, B3…) | **Form** | Monochrome mono chip with a border; tinted only at the extremes |

### Every card section carries a visible label

`SO WHAT` · `EVIDENCE` · `WHY THIS SCORE` · `HOW THIS WAS PRODUCED`, set in `--fs-meta`, uppercase, letter-spaced, in the muted token. This is what makes a dense card scannable rather than a wall — the reader's eye lands on the label first.

### Responsive

| Breakpoint | Navigation | Content |
|---|---|---|
| ≥ 1280px | Sidebar, 248px, labels visible | Cards max-width 900px, centred |
| 900–1279px | Icon rail, 68px, tooltips | Cards fill available width |
| < 900px | Top bar + bottom tab bar (5 primary destinations) | Cards full-bleed, tables scroll in their own container |

## Global Constraints

- **Fixtures are ground truth and read-only.** If a component needs a field a fixture lacks, that is a contract gap — report it, do not edit the fixture.
- **No hardcoded colours, sizes or spacing in components.** Everything is a CSS custom property from `tokens.css`. A hex code in a component file is a defect.
- **Navigation is data.** `src/config/navigation.ts` is a single array; adding, removing or regrouping a destination never touches JSX.
- **`tsc` is not in the build.** Vite 8 transpiles without typechecking; TypeScript 7.0 shipped 2026-08-26 and a deadline is not the place to debug a day-old compiler. Types serve the editor. Add `tsc --noEmit` later if desired.
- **Light mode is primary.** Dark mode is a token override under `prefers-color-scheme`, never a separate design.
- **Versions verified on npm 2026-08-26.** Never write a version from memory; if one fails to resolve, check the registry and report what you found.

## Self-review notes

**Design provenance.** The sidebar IA and status strip come from the Figma output; content, density and card anatomy come from the HTML mockup. The palette, type scale and card disclosure rules are specified here and supersede both.

**The single most important test in this plan** is `so-what is visible without any interaction` in Task 4. It is the mechanical guard against the failure that made the Figma screens feel shallow — if that test is ever weakened, the product regresses to a list of headlines.

**Deliberately not built:** virtualised lists (the budget caps digests at 8 items, so nothing is long enough to need it); a component library dependency (the primitives are ~10 small files and a library would cost more in overrides than it saves); animation beyond CSS transitions; `tsc` in the build.

**Known risk.** Task 8's live-wiring step is where contract drift surfaces. If Plan 3 changed a shape without updating `API_CONTRACT.md`, it appears here as a runtime mismatch. That is the correct place to find it, but budget time for one or two.

**Type consistency.** `NavItem`, `NavGroup`, `Persona`, `SignalType` and the response types in `src/api/types.ts` are transcribed from `API_CONTRACT.md` and used unchanged across every page.
